# R20.1 — Deterministic emission order

**Milestone:** M11 — Emission polish
**Status:** done
**Spec:** §11, R20.1
**Depends on:** R17 (module reachability graph), R20 (the file mechanism)
**Unblocks:** stable diffs; locality extended to files

## Goal

Emission order is depth-first from the top module, children before parents,
ties broken by declaration order. **Never map iteration order.**

## Scope for M11

- [x] Compute the emission order: DFS from top, post-order (children before
      parents), declaration order to break ties among siblings.
- [x] Use only ordered collections (`Vector`, `List`, `Array` with index
      traversal) in the emitter — no `Map`/`Set` iteration whose order is
      unspecified.
- [x] Manifest lists files in this order.

## Exit criteria

- [x] A multi-module design emits in children-before-parents order.
- [x] Adding a module in one file does not reorder unrelated modules' files.
- [x] A grep for `Map(` / `Set(` in the emitter finds none whose iteration
      feeds output order.

## Outcome

Done on 2026-08-12. `Emission` now derives file, report, and manifest order by
walking the immutable IR graph from `Design.top`: instance lists are traversed
in declaration order, modules are appended after their reachable children, and
shared modules are emitted once at their first DFS encounter. External instances
are excluded because ScalaHDL does not emit their module bodies; a missing
internal target is rejected rather than silently producing an incomplete
manifest.

`EmissionDeterminismSuite` scrambles `Design.modules` to prove ordering does not
inherit collection order, covers a shared descendant, checks matching report
and manifest order, and verifies that adding a child preserves the relative
order of unrelated files. The focused suite passes 3 tests; the full build
passes 142 tests. A grep of the emitter package finds no `Map(` / `Set(`
construction whose iteration could feed output order.
